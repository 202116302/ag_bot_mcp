# 스마트팜 데이터마트 환경자료 연결

후속 [환경자료·문헌 질의응답](environment_literature_qa.md)을 구현했다. 이 문서는 데이터 확보 단계 기록이다.

2026-11-16. 사용자 요청에 따라 직접 센서를 연결하지 않고 첨부한 스마트팜 데이터마트 API를 사용한다.
관수는 현재 범위에서 제외한 상태를 유지한다. 새 작업은 내부온도·습도·CO₂ 자료를 확보하고 문헌 비교의 입력으로 준비하는 것이다.

## 연결과 실제 조회

- 첨부 문서: `[PROVIDE]스마트팜_빅데이터_제공 서비스_OPENAPI_기술명세서_v2.0.pdf`,
  `[CROPSEASON]작기별_스마트팜_빅데이터_제공_서비스_OPENAPI_기술명세서_v2.0.pdf`.
- `.env`의 `smartfarm_data` 항목을 사용했다. 키 원문을 소스·로그·문서에 복사하지 않았다.
- 로더 우선순위는 환경 변수의 `SMARTFARM_API_KEY`, `smartfarm_data`, 이후 `.env`의 같은 두 이름이다.
- PROVIDE의 아이덴티티 → 같은 userId의 작기 → 시설·날짜·항목별 환경자료 순서로 조회했다.
- 성공한 실행은 최대 6회 요청: 아이덴티티1 + 작기1 + 환경4. 재시도나 전체 작기 수집은 하지 않았다.
- 최초 제한 환경에서의 연결 실패도 별도 폴더에 남겼다.

선택 방법은 목록의 첫 토마토 시설에서 가장 최근 종료된 작기의 종료일을 조회하는 제한된 탐색이다.
대표 표본이나 가장 최근까지 환경값이 수집된 농장이라는 의미는 아니다.

| 항목 | 실제 확인 |
|---|---|
| 시설 | `PFS_0000001_01` |
| 사용자 | `PFS_0000001` |
| 토마토 품목코드 | `080300` |
| 조회 날짜 | **2023-07-25** |
| 참고 작기 | 5957, 2022-09-21∼2023-07-25 |
| 재배방식 코드 | 응답 null, 추정하지 않음 |
| 비료 필지와 동일 농장 여부 | 연결 근거 없음 |

환경자료는 시설·날짜로 조회했고 응답에 작기 ID가 없다. 작기 정보는 사용자 단위로 조회했다.
따라서 ‘같은 사용자 및 작기 기간 안의 날짜’에 근거한 연결이며 해당 시설과 작기의 직접 매핑을 확인한 것은 아니다.
이 정보는 스냅샷의 `season_linkage`에 기록했다.

## 확보한 값

| 코드 | 문서의 항목명 | 레코드 수 | 원시 최솟값 | 원시 최댓값 | 상태 |
|---|---|---:|---:|---:|---|
| TI | 내부온도 | 24 | 24.67 | 32.33 | available |
| HI | 내부습도 | 24 | 76.33 | 97.00 | available |
| HI02 | 내부 상대습도 | 0 | — | — | no_data |
| CI | 내부CO₂ | 24 | 401.00 | 506.00 | available |

합계 72개 측정 레코드다. 명시적 상대습도 코드 HI02의 부재를 HI 값으로 자동 대체하지 않는다.
HTTP 성공과 업무 상태 `00`을 분리하고 `03 NODATA_ERROR`는 수치 0으로 바꾸지 않았다.

이번 API 명세의 환경 응답에는 단위 필드가 없고, 실제 응답의 standardCategory·standardElement·standardType도 null이었다.
항목명만으로 ℃·상대습도%·ppm 단위를 확정해서 붙이지 않았다. 외부의 다른 데이터셋 단위를 이 시설 응답에 대신 적용하지 않는다.
측정 시각의 시간대와 senVal의 집계 방식도 명시되지 않아 그대로 미확인으로 보존했다.
따라서 위 값은 단위를 확정한 문헌 기준 비교 결과가 아닌 원시 숫자 범위다.

## 구현

- `src/agri_dss/smartfarm.py`: 키 로딩, 허용된 PROVIDE 요청, 키 마스킹, 업무 상태·자료 정규화,
  시설·품목·분야·항목·날짜 일치, 중복 시각·비정상 수치 검사, 스냅샷 출처 검증.
- `scripts/probe_smartfarm_environment.py`: 토마토 농가1곳·완료 작기1개·날짜1일, 최대6회 조회.
- `python -m agri_dss environment`: 저장된 과거 자료의 요약. `--json`으로 전체 스냅샷을 읽는다.
- MCP `get_environment_data(snapshot_id="SMARTFARM-PFS_0000001_01-20230725")`: 서버에 등록한 같은 스냅샷만 조회.

키를 포함한 실제 요청 URL은 기록하지 않고 `{serviceKey}` 템플릿을 저장한다.
응답에 키가 되돌아오면 저장 전에 마스킹하며 네트워크 예외 상세는 기록하지 않는다.
원본에 없는 단위·시간대·품종·생육단계는 null 또는 미확인으로 둔다.
정규화값은 Decimal 문자열로 저장하고 음수 온도·0·결측을 구분한다.
출처 해시는 저장 레코드의 정렬된 표준 JSON을 대상으로 계산하며 `source_hash_scope`에 범위를 명시했다.
스냅샷을 읽을 때 원본에서 재정규화한 결과와 비교한다.

## 저장 위치와 재실행

- 성공 조회 원본·조회 요약: `outputs/smartfarm_environment/20261116T073643721744Z/`.
- 최초 연결 실패: `outputs/smartfarm_environment/20261116T072921919263Z/`.
- 키가 마스킹된 환경 원본4개: `data/references/smartfarm/environment_20230725/`.
- 고정 환경 스냅샷: `data/snapshots/smartfarm_environment_20230725.json`.

```powershell
$env:PYTHONPATH = 'src'
$env:PYTHONIOENCODING = 'utf-8'
python -m agri_dss environment
python -m agri_dss environment --json
```

위 조회는 네트워크·키가 필요 없다. 외부 자료를 다시 소량 확인할 때만 다음을 실행한다.

```powershell
python scripts/probe_smartfarm_environment.py
```

재조회는 새 outputs 폴더를 만들며 등록된 고정 스냅샷을 자동 덮어쓰지 않는다.
종전 `scripts/probe_apis.py`의 키 로딩 방식은 변경하지 않았다. 새 `.env` 별칭은 이 전용 클라이언트가 지원한다.

## 검증과 다음 단계

전체 자동 테스트 **197 passed**. 키 우선순위·인코딩 마스킹·예외 비노출·업무 오류·0/결측/음수 온도·비정상 수치·
시설/항목/날짜 오류·시각 중복·원본 변조 차단·CLI와 실제 stdio MCP 환경 도구 조회를 포함한다.

현재 완료 범위는 데이터마트 연결·과거 환경자료 확보·보관·조회다.
기존 `ask`는 여전히 선택 필지 비료 처방용이며 새 환경 도구를 모델에 공개하지 않는다.
후속 `environment-ask`에서 과거 환경자료와 관련 문헌을 함께 보여주는 GPT 경로를 연결했다.
환경 적합성·설비 제어 판정은 보류 상태다. 최신 구현·검증은 위 질의응답 문서를 따른다.

다음 순서는 다음과 같다.

1. 이 서비스/시설에 대한 단위·HI 의미·시간대·집계 방식의 근거를 확보한다.
2. 재배문서에서 토마토 유형·시간대·생육단계가 명확한 온습도 기준을 출처와 함께 분리한다.
3. **과거 환경자료와 문헌을 함께 보여주는 질의응답**을 별도 경로로 만든다.
   조건이 확인되지 않은 경우 수치 적합성 판단을 보류하고 참고 범위를 제시한다.
4. 확인된 조건에서 같은 환경 스냅샷과 문헌을 RAG/MCP 양쪽에 제공해 조회·계산·설명 보존을 평가한다.

직접 센서 연결이나 현재 온실의 실제 제어 명령은 이 계획의 전제가 아니다.
