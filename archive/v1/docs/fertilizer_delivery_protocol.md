# 비료 처방 전달·근거 추적·반복 일관성 평가

2026-11-16 사용자 결정에 따른 현재 실험 범위다. 관수는 노지·시설 등 적용 조건의 차이를 고려해
이번 평가에서 제외했다. 기존 관수 코드·문헌 검토·합성 시험은 보관하며 현재 비료 결과와 합산하지 않는다.

최초 전체 질문집의 Mock 및 실제 GPT 10회 반복 결과는 [실측 결과](fertilizer_delivery_results.md)에 정리했다.

## 평가 질문

고정된 공급자 비료 처방을 MCP 도구로 읽거나 같은 자료를 RAG로 전달했을 때,
모델이 수치·단위·식별자·출처·자료 한계를 얼마나 보존하며 반복 응답이 일관적인지 확인한다.
현재 MCP는 Python 시비 규칙을 계산하지 않는다. 따라서 두 경로는 자료 전달 방식의 비교이며,
농업적 판단 정확도 또는 MCP 프로토콜 자체의 효과를 분리 측정하는 실험이 아니다.

## 고정 자료와 참조값

- 대상 PNU `5271033027105280033`, 시험 작물 `04017` 시설 토마토.
- 원본 `data/references/fertilizer/wanju_tomato_20261115.json`.
- 원본 SHA-256 `cb894d73957c68b6ba45d40e17041db72ebd04b34a2b2e2279fc1471eb074e35`.
- 고정 참조값과 질문 `configs/scenarios/fertilizer_delivery.json`.
- 밑거름 N/P/K `14.4 / 3.0 / 3.0`, 웃거름 `10.9 / 0.0 / 0.0`, 퇴비 4종 `0`, 단위 `kg/10a`.

참조값은 원본 XML의 필드와 직접 대조한 전사값이다. 앱의 정규화 결과나 Mock 답변에서 기대값을
자동 생성하지 않는다. 실행 전에 원본 파일 해시·업무 성공·필지/작물·원본 필드별 수치를 대조한다.
이는 전사 충실도에 대한 별도 평가 기준이며 농업적 적정 시비량의 독립 정답은 아니다.
단위는 기존 API 명세 검토의 `kg/10a` 계약을 사용한다.

실제 재배 작물, 검정일자, 적용 적합성은 미확인이다. 자료의 한계 고지를 검사한다.
10개 비료 성분 중 결측값은 없다. 따라서 실제 비료량 null의 모델 처리 성능은 이번 결과로 측정할 수 없다.
0/null 구별과 비정상값은 별도 자동 테스트에서 변조 응답으로 검증한다.

## 질문과 표본

| 종류 | 사례 | 모델 실행 |
|---|---|---|
| 처방 전달 | 전체 처방·한계 | 실행 |
| 처방 전달 | 밑거름·웃거름 N/P/K | 실행 |
| 처방 전달 | 퇴비·0 값 보존 | 실행 |
| 처방 전달 | 출처·실제 작물·검정일자·한계 | 실행 |
| 로컬 지원 범위 검사 | 미등록 PNU | 사전 보류, 0회 |
| 로컬 지원 범위 검사 | 미등록 작물 | 사전 보류, 0회 |

이 질문들은 같은 처방 문서 1개를 다른 표현으로 요청한다. 서로 독립적인 농장 4개가 아니다.
현재 모델 계약은 질문의 초점과 관계없이 성분 10개 전체를 출력한다. 요청한 항목만 골라 답하는 능력은 평가하지 않는다.
관수·기상·생육·환경제어 질문은 현재 사례집에 포함하지 않는다. 기존 구조화 자료 범위 고지는 유지한다.

## 경로와 동일 조건

MCP는 모델의 `get_fertilizer_prescription` 함수 선택에 따라 실제 stdio 서버가 저장된 처방을 조회한다.
RAG는 PNU·작물 일치 필터로 같은 정규화 문서 1개를 골라 입력에 직접 넣으며 도구를 호출하지 않는다.
이는 정확한 메타데이터 검색이며 임베딩·문헌 검색 품질 평가가 아니다.

각 질문·반복에서 모델 버전·추론 수준·설정·원본/정규화 자료·코드·질문·응답 스키마와 로컬 분기를 확인한다.
실행 도중 변경되면 비교 조건 불일치로 기록한다. 반복마다 경로 실행 순서를 바꾸고 자동 재시도하지 않는다.
기대 참조값과 평가 라벨은 실행 함수에 전달하지 않으며 평가기에만 사용한다.

## 점수와 실패 처리

`src/agri_dss/fertilizer_evaluation.py`는 런타임의 `check_explanation`과 별도로 마지막 원시 모델 응답을 읽는다.
필터링된 구조화 답변이나 한국어 템플릿을 대신 평가하지 않는다. 실패 후 과거 정상 응답으로 되돌리지 않는다.

| 지표 | 판정 조건 |
|---|---|
| 원시 수치 보존 | 성분 10개가 중복·누락 없이 정확한 Decimal 수치를 유지; 0과 null 구별 |
| 원시 단위 보존 | 성분별 `kg/10a` 유지 |
| 원시 식별·출처 보존 | PNU·작물·업무 상태·원본 SHA-256 유지 |
| 원시 한계 고지 보존 | 필수 notice 목록을 중복·누락 없이 유지 |
| 근거 추적 | 도구/검색 기록에 선택 필지·작물·원본 해시가 있고, RAG 정규화 해시도 일치 |
| 검증된 전달 성공 | 위 검사 통과 + 정상 완료 + 런타임 검사 통과 + 출력 존재 |
| 반복 일관성 | 정규화된 원시 구조화 응답의 최빈 값 횟수 / 전체 시도 횟수 |
| 로컬 보류 성공 | 미등록 요청이 보류되며 모델·도구·검색 호출이 없음 |

`14.4`와 `14.40`, 성분과 고지의 배열 순서 차이는 동일하게 취급한다. 단위 차이·0/null 차이는 유지한다.
반복 일관성은 정확성과 별개다. 같은 틀린 값을 반복하면 일관성은 높고 수치 보존 점수는 낮을 수 있다.
반복 1회에서는 일관성 비율을 null로 둔다.

모델 오류·거절·불완전 응답·파싱 실패·런타임 충돌·누락/손상 로그는 전체 모델 시도 분모에 남긴다.
로컬 보류는 모델 시도 분모에서 제외하고 별도 개수로 보고한다. 실행 조건 불일치는 전체 통과를 차단하며,
그런 실행의 원시 점수를 동일 조건의 비교 성능으로 해석하지 않는다.
한계 고지는 구조화된 항목만 평가하며 자유서술 전체의 사실성·질문 이해 능력을 평가하지 않는다.

## 실행과 재현

```powershell
python scripts/compare_fertilizer_paths.py --suite --repeats 10
python scripts/compare_fertilizer_paths.py --suite --provider openai --repeats 10 --case prescription_full --case unregistered_parcel --case unregistered_crop
python scripts/compare_fertilizer_paths.py --analyze outputs/fertilizer_delivery/<실행시각>
```

`--suite`는 고정 질문집, `--case`는 부분 선택, `--repeats`는 1∼10회다.
기존 단일 질문 비교 명령은 유지된다. `--analyze`는 모델/API 호출 없이 저장 자료만 읽고 재집계한다.

실행 폴더:

- `protocol.json`: 질문·참조값·설정·원본/코드 해시·평가기 해시.
- `evidence.json`: 실행 시 고정한 정규화 자료. 없거나 해시가 달라지면 비교 조건 실패.
- `01_<case>_<path>.json` 등: 원시 모델 응답·usage·오류·도구/검색 기록·시간.
- `results.csv`: 시행별 원시 지표·전달 성공·조건 일치 여부.
- `summary.json`: 경로별 집계·사례별 반복 일관성·쌍별 응답 일치.
- `report.md`: 저장 결과에서 생성한 보고서.

자동 테스트 **175 passed**. 참조 전사 검증, 차단된 수치 오류 포착, 0/null·NaN·단위·출처·고지·중복 오류,
일관되게 틀린 응답의 별도 집계, 보류 분모 분리, 누락 로그 및 고정 자료 변조 처리를 검증했다.

## 해석과 후속 작업

단일 필지·작물·저장 처방에 대한 제한된 전달 비교다. Mock은 결정적 시험 대역이며 GPT 성능이 아니다.
두 경로가 모두 잘 작동해도 농업적 처방의 적합성이나 한 방법의 우월성을 입증하지 않는다.
확장은 여러 실제 필지·작물·조회 상태의 자료를 구분해 고정한 뒤 진행한다. 자료 없음·성분 결측을 임의로
실제 응답처럼 만들지 않는다. 후속 실제 모델 평가에서는 질문 표현과 자료를 넓히고 실패 사례를 추가해야 한다.
