# 합성 관수 직접 판정 비교와 문헌 검토

현재 관수는 사용자 결정으로 실험 범위에서 제외했다. 이 문서는 보관 기록이며,
진행 중인 실험은 [비료 처방 전달 평가](fertilizer_delivery_protocol.md)다.

구현·검증일: 2026-11-16. 비료 전달 비교 다음 단계로 직접 판정 경로와 평가 기록을 구현했다.
현재 결과는 합성 소프트웨어 시험이다. 토마토 실제 관수 처방이나 농업 정확도는 평가하지 않았다.

후속 [문헌 정밀 검토](tomato_literature_review.md)에서 PDF132쪽의 명시적 관수개시점 −20 kPa를 확인했다.
아래 43/249쪽의 범위 차이 검토에 추가되는 우선 후보이며, 실제 필지 적용·경계 형식화는 별도로 남아 있다.

## 문헌 기준 검토

기존 추출문과 PDF 원본 이미지 43·249쪽을 다시 대조했다. 입력 PDF의 SHA-256은
`70a46a767fd4cadd2b5b3a9470bb0b6cb4677742e7dfea2c0ef7d6b023ff1c7f`다.

| 절 | PDF/인쇄 쪽 | 초기 단계 관리 범위 | 후기 단계 관리 범위 |
|---|---|---|---|
| 마. 토양수분 | 43/40 | 생육 전반기 10∼30 kPa | 후반기 3∼10 kPa |
| 다. 토양수분과 관수 | 249/246 | 생육 초기∼착과까지 20∼30 kPa | 착과 이후∼수확기 10∼20 kPa |

범위의 단계 정의와 적용 맥락이 다르므로 합치거나 평균하지 않았다. 각 범위의 상한을 넘으면
관수를 시작한다는 이진 규칙과 경계 연산자 `>`·`>=`를 원문에서 확정할 수 없어 실행 규칙으로 승격하지 않았다.
기계 판독 검토 기록은 `configs/rules/candidates/tomato_moisture_review.json`이며
`candidate_not_executable` 상태다. `verified` 규칙의 대체물로 로딩하지 않는다.

원본 대조 이미지: `outputs/source_review/tomato_43.png`, `tomato_249.png`.
선택 실제 필지의 재배방식·생육단계·센서 단위/부호·수분 관측값은 여전히 미확인이다.
별도 농장·작기의 센서값이나 현재 기상을 선택 필지에 임의로 결합하지 않았다.

## 비교 경로

| 항목 | RAG | MCP |
|---|---|---|
| 입력 | 합성 스냅샷과 검색한 기준 원문 | 같은 합성 스냅샷, 서버 소유 규칙 |
| 판정 | 실모델이 문서의 순서·조건·경계를 직접 해석 | Python evaluate_irrigation이 실제 stdio 도구 안에서 판정 |
| 모델 역할 | 직접 결정과 사유 코드 출력 | 도구 선택·호출 후 판정·사유 보존 |
| 런타임 검사 | 스키마·출처·사례 메타데이터 | 같은 검사와 도구 판정 변경 차단 |
| 기대 정답 | 평가기에만 전달 | 평가기에만 전달 |

RAG에는 Python 판정·계산 기록·기대 라벨·규칙 JSON을 제공하지 않는다. 직접 해석에 필요한
기준 원문과 스냅샷을 제공한다. 검색은 합성 규칙 ID로 문서 1개를 찾는 메타데이터 방식이며 벡터 검색은 아니다.
RAG가 유효한 형식으로 틀린 판정을 반환해도 Python 정답으로 덮어쓰지 않고 실행 로그와 평가 결과에 보존한다.
MCP 설명이 도구 판정과 다르면 `conflict`로 기록하고 설명을 출력하지 않는다.

Mock RAG는 Python 엔진 기반 대역이다. 네트워크 없이 경로·스키마·기록을 시험하는 용도이며,
Mock의 반복 일치로 RAG 직접 추론의 정확성이나 GPT 성능을 주장하지 않는다.
실제 GPT 3개 사례는 이 대역을 사용하지 않았다.

## 사례와 평가

`configs/scenarios/irrigation_decisions.json`에 기대 판정·사유를 수작업으로 고정했다.
규칙은 `configs/rules/demo/irrigation.json`, 원문은 `data/references/demo/irrigation.md`다.
합성 기준은 부피수분함량 **20% 미만**이며 실제 농업 근거에서 가져온 수치가 아니다.

- 경계: 19.9 → 필요, 20.0 → 불필요, 20.1 → 불필요.
- 0과 결측: 0.0 → 필요, null → 정보 부족.
- 적용 조건: 다른 작물·단계·재배방식·단위 → 정보 부족.
- 입력 범위: 101% → 정보 부족.

질문은 고정하고 사례별 입력만 바꾼다. 연구 명세의 별도 수량 계산·복합 기상 조건은 아직 포함하지 않는다.
모델·설정·스냅샷·규칙·기준 원문·코드·응답 스키마 해시를 비교한다.
경로 실행 순서는 반복마다 바꾸고 각 시행의 run_id, 원시 응답, usage, 도구/검색 기록을 보존한다.

판정 일치 수와 판정+사유 코드 일치 수를 나누어 집계한다. 모델 실패·파싱 실패·충돌·누락/손상 로그도
전체 시도 분모에 포함한다. 경로 간 일치는 동일 조건·양쪽 완료인 쌍에서만 기록한다.
반복 일치성은 사례별 유효 응답의 최빈 판정 횟수 / 전체 시도 횟수로 기록하고 실패는 분모에 남긴다.
반복 1회인 점검의 반복 일치성은 null이다. 이 수치는 독립 농업 정답 기반 정확도와 구분한다.

## 실행과 산출물

```powershell
$env:PYTHONPATH = 'src'
$env:PYTHONIOENCODING = 'utf-8'
python -m agri_dss irrigation-ask --path rag --case SYNTHETIC-EQUAL
python scripts/compare_irrigation_paths.py --repeats 10
python scripts/compare_irrigation_paths.py --provider openai --case SYNTHETIC-EQUAL --case SYNTHETIC-MISSING --case SYNTHETIC-UNIT
python scripts/compare_irrigation_paths.py --analyze outputs/irrigation_comparison/20261116T053321152711Z
```

`irrigation-ask`는 실제 필지 질의와 별도로 실행하며 `--provider`, `--path`, `--case`, `--output`을 받는다.
MCP 서버는 등록된 합성 ID만 조회하고 임의 파일 경로나 실제 PNU를 관수 사례로 사용하지 않는다.
연구 모드에서 합성 규칙을 실행하는 기존 차단은 유지된다.

비교 실행 폴더에는 `protocol.json`, 시행별 원본 JSON, `results.csv`, `summary.json`, `report.md`가 있다.
CSV는 외부 분석에 사용할 수 있다. 현재 산출물로 실제 농업 성능의 포스터 그래프를 만들지는 않았다.

5. 그 실측 결과로 연구 지표와 포스터 그래프를 생성한다.
